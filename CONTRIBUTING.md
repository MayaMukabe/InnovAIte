# Contributing

## Workflow

1. Create a focused branch from `main`.
2. Keep changes small and product-scoped.
3. Run `npm run lint`, `npm run test`, and `npm run build`.
4. Document user-facing or architectural changes.
5. Open a pull request describing purpose, screenshots, checks, accessibility impact, and responsible-AI impact.

Use Conventional Commits:

- `feat:` user-facing capability
- `fix:` defect correction
- `docs:` documentation only
- `refactor:` internal change without behavior change
- `test:` test coverage
- `chore:` tooling or maintenance

## Definition of done

- Keyboard access and visible focus are preserved.
- Mobile and desktop layouts are checked.
- Student-facing language is encouraging and age appropriate.
- Correctness does not depend on generative-model output.
- New data collection is documented and reviewed.
- Lint, automated tests, and production build pass.

Do not commit credentials, student information, generated production data, or unlicensed assets.
